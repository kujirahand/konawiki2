# セキュリティ監査記録 (konawiki2)

定期セキュリティチェックとして実施した監査の記録。
対象はコア全体 (`kona-engine/lib`, `index.php`)、アクション全般
(`kona-engine/action`)、プラグイン全般 (`kona-engine/plugins`)。
konawiki3 の定期監査で見つかったパターン (掲示板管理パスワード既定値、
非公開ページの検索漏洩、SVG 配信、添付 CSRF、テンプレート `extract`、
skin 拡張子、include 再帰・symlink) を konawiki2 の実コードと照合し、
再現できた問題だけを修正した。
検証は使い捨てコピー + `php -S` + curl の実機スモークと、
回帰テスト `tests/security31.test.php` で行った。

## 修正した問題

### 認証・認可

1. **編集用 auth ハッシュが未発行のページを未認証で書き換えできた (高)**
   - `action_edit_update` / `action_edit_api__write` は、サーバー側の
     `login_auth_hash` とリクエスト値の一致で認証済みとみなしていたが、
     両方とも空文字の場合 (`'' == ''`) にも一致扱いになっていた。
   - 初期投入ページ (FrontPage 等、`log_auth_hash` に行がないページ) は
     ログインなしの POST で本文を書き換えできることを実機で確認した。
   - 空でないハッシュ同士を `hash_equals` で比較した場合のみ認証済み
     とするよう変更。
2. **ログイン試行回数の制限が login アクションでしか効かなかった (中)**
   - 制限チェックは `action/login` 内だけにあり、編集画面などの認証
     フォーム (共通処理 `_konawiki_auth_form`) からは無制限に試行できた。
   - 認証の共通処理側でも、同一 IP の失敗が24時間に10回以上なら拒否
     するよう変更 (login アクション側の従来条件と同一)。
   - あわせてパスワード照合 (平文 / md5 / sha1) を緩い `==` から
     `hash_equals` に変更し、`0e...` 形式同士の緩い比較で別パスワードが
     通ってしまう問題 (magic hash) を防いだ。
3. **セッション Cookie の属性 (中〜低)**
   - `konawiki_start_session` で `HttpOnly` / `SameSite=Lax` を付け、
     HTTPS 時は `Secure` も付けるよう変更。

### 非公開ページ (private) の漏洩

表示系 (show / text / html 等) は private ページの本文を伏せる実装に
なっているが、以下の経路は private を考慮しておらず、未ログインで
ページ名・本文抜粋・キーワードの存在確認ができた (実機で確認)。

4. **検索 (search) が private ページを返した (高)**
   - 名前検索・本文検索・タグ検索・バックリンク検索の全てに
     `COALESCE(private,0)=0` の条件を追加。本文検索は private 本文に
     キーワードが含まれるかどうかのオラクルになっていた。
5. **RSS / RSS2 が private ページの名前と本文抜粋を配信した (高)**
   - `action_rss_cmd` の抽出 SQL に private 除外条件を追加。
6. **#page プラグインが private ページを埋め込んだ (高)**
   - 書き込み権限がない閲覧者には埋め込まないよう変更。
7. **その他の列挙系の private 除外漏れ (中〜低)**
   - #tag / #navi / #countpages プラグイン: private 除外条件を追加。
   - #recentcomment プラグイン: private ページのコメント (ページ名含む)
     を表示しないよう変更。
   - show の関連ページ (タグ経由) 一覧: private ページ名を表示しない。
   - `[[[ページ名]]]` の説明表示: private ページは本文抜粋とタグ情報を
     出さず、リンクのみ表示するよう変更。

### ファイル・プラグイン

8. **#textfile プラグインで data 内の設定ファイルを読めた (高)**
   - data フォルダのファイル名を指定する仕様のため、
     `#textfile(konawiki.ini.php)` で管理キーや認証情報を含む設定
     ファイルがそのまま表示できた (ページ経由・plugin アクション
     経由の両方で実機確認)。
   - ファイル名を `basename` に限定し、php / db / sqlite / ini 等の
     拡張子と `konawiki.ini.php` を拒否。実パスが data 直下にあること
     (symlink で外を指していないこと) も確認するよう変更。
9. **Wikiリンクの URL キャプションが未エスケープだった (中)**
   - `[[キャプション:https://...]]` 形式で、キャプション側だけ
     `htmlspecialchars` を通っておらず、HTML をそのまま出力できた
     (保存型 XSS)。キャプションをエスケープするよう変更。
10. **&color プラグインの色指定が style 属性を注入できた (中〜低)**
    - 色として正しい形式 (#hex / 色名) だけを受け付け、不正な値は
      `inherit` に落とすよう変更 (konawiki3 の color_talk と同種の対策)。
11. **#vote プラグインの選択肢・得票数が未エスケープだった (低)**
    - DB に保存された選択肢を `htmlspecialchars` して出力するよう変更。
12. **コメント系プラグインの1行項目に改行を注入できた (低)**
    - #comment の名前、#article の件名・名前、#bodycomment の名前・
      コメントは1行の挿入文に埋め込まれるため、改行を含むと行単位の
      Wiki記法 (プラグイン行など) を注入できた。改行を取り除くよう変更。
13. **rakuten プラグインのキャッシュが `unserialize` だった (低)**
    - data 内キャッシュファイルの読み込みを JSON に置換
      (書き込みも `json_encode` に変更)。
14. **shop_cart の顧客パスワードが固定 salt + sha256 だった (中〜低)**
    - 保存を `password_hash` に変更。ログイン時は新形式を
      `password_verify`、旧形式は互換のため `hash_equals` で検証する。

### CSRF

15. **添付アップロード (attach&write) に edit_token が無かった (中)**
    - 削除・更新にはトークン検証があったがアップロードには無く、
      フォーム側にもトークンが埋め込まれていなかった。
    - ハンドラ側に検証を追加し、アップロードフォームにも
      `edit_token` の hidden フィールドを追加。
16. **編集履歴の削除 (edit&removebackup) に edit_token が無かった (中〜低)**
    - 検証を追加し、履歴一覧の削除フォームにもトークンを追加。

### 状態管理・その他

17. **show のキャッシュ消去が未認証で実行できた (中〜低)**
    - `cache.mode=cache` のとき `?cache=clearall` 等で誰でも
      キャッシュ DB を全消去できた。書き込みログイン中のみ実行する
      よう変更。
18. **削除した添付ファイルの実ファイルが残っていた (中)**
    - 実ファイルは `{id}{拡張子}` で保存されるのに、削除処理は
      拡張子なしの `{id}` だけを `unlink` していたため、削除後も
      直接 URL でアクセスできた。attach 削除とページ削除の両方で
      拡張子付きファイルも削除するよう変更。
19. **meta_table の非表示切替が反映されなかった (中)**
    - 更新 SQL のパラメータ順が誤っており (private=1 側は順序違い、
      private=0 側は2プレースホルダに連結文字列1個)、「ページを
      表示しない」を選んでも public のままになっていた。両分岐とも
      `[time(), $log_id]` に修正。
20. **`include_template` (旧テンプレート経路) の `extract` 上書き (中・潜在)**
    - テンプレート変数で include 先の `$path` を上書きできた。
      呼び出し側優先で変数を合成し、内部変数と同名のキーを除いて
      から `extract` するよう変更。

## PR #33 レビュー後の追加修正

- 説明付きリンク (`[[[ページ]]]`) を含むページは、閲覧者の権限に
  応じて本文抜粋・タグの表示が変わるため、共有 HTML キャッシュに
  保存しない。修正前のキャッシュも再利用せず、新形式で再生成する。
- 添付の実ファイル削除は表示名の拡張子に依存させず、数値 ID に
  対応する `{id}.*` と拡張子なしの旧形式を全て削除する。添付単体の
  削除とページ削除で同じ処理を使い、両形式が同時にある場合も残さない。
- 添付フォームは匿名セッションにも CSRF トークンを発行する。
  `auth.write.enabled=FALSE` でもアップロードでき、トークンなし・
  不正トークン・別セッションのトークンは拒否する。認証有効時の
  書き込み権限確認は維持する。

HTTP 回帰テスト: `python3 tests/security31_http.py`

- PHP (mbstring / SQLite) と初期化済み `kona-engine/fw_simple` が必要。
- 設定・DB・添付・キャッシュは一時ディレクトリ内に作成し、実データは使わない。
- 上記3件に加え、静的ページのキャッシュ、通常の添付削除、旧形式の
  同時削除、別 ID のファイル保護、既存テスト (security31 / basic) を検証する。

## 問題なしを確認したもの

- SQL インジェクション: コア・アクション・プラグインの DB アクセスは
  概ね prepared statement 化されており、文字列補間は整数化済みの値
  (intval 済み id / time 等) のみだった。
- file アクション: ファイル名を英数字・ドット等のみに制限しており、
  パストラバーサルは成立しなかった。対象は resource ディレクトリ内のみ。
- go アクション: 数値 ID からの DB 内ページ名へのリダイレクトのみで、
  オープンリダイレクトは成立しなかった。
- 添付アップロードの拡張子制限: MIME マップにない拡張子 (.php 等) は
  `application/octet-stream` として拒否される。SVG も同マップに無く
  アップロードできないため、kona3 のような SVG 保存型 XSS は不成立。
- html / htmlshow プラグイン: 既定で `plugins.disable` により無効。
- import / export: ログイン認証 + 管理キー (import) が必須。
  PHP serialize 形式の import は「未対応」として拒否される。
- freeze: 管理キーの照合 (`konawiki_checkPassword`) は `hash_equals`
  使用済み。edit の rename / replace / batch 系コマンドも認証 +
  edit_token + 管理キーが必須。
- comment / article の編集モード: 認証フォームを経由する。
  vote の CSV 編集も認証必須。
- counter の履歴表示 (plugin 経由) はログイン必須になっていた。
- #page プラグインの自己・相互参照: 「表示中」チェックにより無限
  再帰は成立しないことを実機で確認した (自己埋め込みページを表示
  しても再帰せず打ち止めになった)。
- テスト用アクション (test) は debug 設定が有効なときだけ動作する。

## フォローアップ (別 Issue #32 で扱う残件)

以下は今回の PR では修正せず、フォローアップ Issue #32 に切り出した。

- テンプレート設定ファイルの初期値に既知の管理キー (`konawiki`) と
  ユーザー (`username` / `password`) が有効な状態で入っており、
  初回起動時にそのまま実設定へコピーされる。初期値を無効化するか
  初回セットアップで変更を強制するかは仕様判断が必要。
- テンプレートエンジン (`kona-engine/fw_simple`, サブモジュール =
  php_fw_simple リポジトリ) の `extract()` が引数で内部変数を
  上書きできる問題。konawiki2 側の呼び出しではリクエスト由来の
  キーは渡らないため潜在的な問題だが、修正はサブモジュール側
  リポジトリで行う必要がある。
- Wiki ユーザーのパスワード保存形式 (平文 / md5 / sha1) を
  `password_hash` 形式へ拡張すること (設定ファイル形式の互換判断が必要)。
- `HTTP_HOST` から baseurl を組み立てる箇所があり、Host ヘッダに
  よって生成リンクが変わる (プロキシ環境との兼ね合いで今回は不変更)。
- meta_table の新規作成 (m2=new) が GET でページを作成する点と、
  bodyvote / bodycomment が freeze 中のページにも書き込む点は、
  既存の利用方法との互換を確認してから判断する。
- plugin アクションは任意プラグインの convert を直接実行できる設計
  であり、個別プラグイン側での権限確認が前提になっている
  (今回 #page / #textfile は個別に修正済み)。
